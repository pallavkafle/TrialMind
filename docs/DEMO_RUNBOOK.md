# TrailMind: Demo Runbook

## The Day Before
* **Back up** `ml-service\routing\osm_cache` (about 24 MB, took hours to build), `backend\.env` and `ml-service\.env` to a USB stick or a private cloud folder.
* `git status` is clean; the latest code is pushed.
* `cd backend`, `node scripts/seed-demo.js` (or `--reset` then seed for a clean slate), then `node scripts/golden.js`: no FAIL, no changes.
* `venv\Scripts\python.exe -m pytest` (in ml-service) and `npm test` (in backend) are green.
* `docs\evidence\RESULTS.md` and the charts are in the report.
* Fresh `app-debug.apk` installed on a **real phone**; Gemini key valid (`GEMINI_API_KEY`), mobile data/Wi-Fi and `https://trailmind.pallavkafle.com.np/api/health` confirmed.
* Phone fully charged; charger and a USB cable in the bag; screen timeout set to 10 minutes.

## Start-up Order (About 2 Minutes, Do It 15 Minutes Before)
1. Run `.\start-trailmind.bat` from `C:\D_Drive_Backup\PROJECTS\trailmind` — this launches MongoDB, the Python ML service (`port 8000`), the Node backend (`port 5000`), and the permanent `trailmind` Cloudflare tunnel together.
2. Wait until the launcher prints `OK: ML service`, `OK: Backend`, and `OK: Public address` (`https://trailmind.pallavkafle.com.np`).
3. Confirm `http://localhost:8000/health` shows `model_loaded: true`.
4. Warm up once on the phone: log in, open Places, create one itinerary (the first Gemini call is the slowest).
5. *(Backup only)* If venue internet fails completely, switch to USB cable (`adb reverse tcp:5000 tcp:5000`) and set the app's Server Address in Settings to `http://127.0.0.1:5000/`.

## If Something Goes Wrong
| Problem | What to do |
|---|---|
| Error `530`, `502`, or `524` on the phone | Tunnel or backend stopped; re-run `.\start-trailmind.bat` on the PC and wait for `OK: Public address`. |
| Gemini is slow or down | The app uses a template plan after at most 35 s and says so in an amber note. Keep talking; this is a designed fallback. |
| ML service down | Places and permits still work; say that the destination list is kept in Node. Restart it and continue. |
| Venue Wi-Fi/data has no internet | Connect USB cable, run `adb reverse tcp:5000 tcp:5000`, and switch Server Address in Settings to `http://127.0.0.1:5000/`. |
| A screen shows nothing | Pull the "Retry" button; if it persists, restart the backend. |

## Questions You May Be Asked (Answer Honestly)
* **Is the budget "AI"?** The itemized formula is the primary number. The Random Forest is an independent cross-check. Evidence and caveats are in `docs/evidence/RESULTS.md`.
* **Why a Random Forest, when Gradient Boosting has a lower error?** Check `RESULTS.md` and decide your reason before the defense; do not claim the Random Forest is the most accurate model.
* **How was the dataset made?** State clearly how it was built (`ml-service/data`). If it was assembled or generated by the team and not collected from real bookings, say so.
* **What does Gemini do?** It writes day titles and activities inside a fixed day-to-place plan; if it fails, a template plan is used. It never decides routes, costs or permits.
* **How accurate is the review analysis?** The test set is small and was written with the rules, so it is a regression check; the sentiment model is independent of the rules.
* **Are the permit fees official?** They were researched on the date shown in the app and may change; each carries a confidence level and a note to confirm with the agency.
* **Why no hotel booking or prices?** OpenStreetMap has none; the app finds places and lets you call or open their website.
* **Why do routes look straight on the map?** Distances use straight-line distance times a curvature factor; real road distance is longer, and the app says so.
* **Security?** Passwords are hashed, logins use signed tokens, requests are rate-limited, secrets stay out of git.

## Limits to State Openly
* Hospital and hotel data come from OpenStreetMap and can be incomplete; the hospital data covers about 25 km around the 27 destinations.
* Weather is for the destination's coordinate point, not the summit.
* Seeded reviews in the demo are sample data written for testing.
* Only 27 destinations and 7 starting cities; Android only.
